# DPAIAI / DPI Pilot

Android-утилита локального обхода DPI без root. Прототип 0.4.0.

Основана на ByeDPIAndroid (GPL-3.0), ByeDPI и hev-socks5-tunnel. Оригинальная документация: [UPSTREAM_README.md](UPSTREAM_README.md).

Добавлены локальные профили, пять экспериментальных режимов и проверка HTTPS через SOCKS с проверкой сертификата. Добавлен экспериментальный подбор по сервисам; автоматическое переключение сетей пока не реализовано.

Подробности и сборка: [PILOT_README.md](PILOT_README.md). APK после успешной сборки доступен в Artifacts вкладки Actions. Это отладочная сборка; эффективность на конкретном провайдере требует проверки на устройстве.

## Выбор приложений
На главном экране нажмите «Выбрать приложения». YouTube, Instagram, Telegram и их известные варианты отображаются первыми, если установлены; ниже — другие приложения с иконкой запуска. Выберите одно или несколько и сохраните. При применении результата подбора установленный стандартный клиент выбранного сервиса выбирается автоматически. Затем включите обработку. Выбор сохраняется после перезапуска. Для изменения сначала выключите обработку.

В режиме VPN через движок идут только выбранные приложения. Пустой выбор или удаление всех выбранных приложений не включает обработку всего телефона. Ручной режим Proxy в расширенных настройках требует отдельной настройки клиента и не использует выбор приложений. Выбор приложения сам по себе не гарантирует обход блокировки по IP или работу звонков.

## Подбор для сервиса (0.3.0)
На главном экране откройте «Подобрать для YouTube / Instagram / Telegram». Выберите сервис и запустите подбор при выключенной обработке и другом VPN. Кандидаты запускаются по очереди в отдельном процессе :tuner на порту 19080. После проверки процесс уничтожается, C-состояние не переносится между кандидатами. Уход с экрана останавливает подбор. Таймаут кандидата не мешает проверке остальных. Тесты не меняют рабочие настройки до явного применения.

YouTube и Instagram: по два HTTPS-запроса на сайт/API/CDN. Ответы 403/429 подтверждают только достижимость сервера, но не доступ к контенту. Аккаунты, видео googlevideo, Reels и звонки не проверяются.

Telegram: восемь кандидатов (контроль, split, множественный split, disorder, split+disorder, OOB и два fake/TTL), ориентированных на TCP-поток MTProto. Для каждой стратегии проверяются все пять production bootstrap DC, каждый дважды; максимум три DC параллельно. Сначала обфусцированный padded-intermediate MTProto (AES-256-CTR), при неудаче abridged. Начальный req_pq_multi/resPQ проверяется по длине, типу и nonce, без аккаунта и создания ключа. Это не аутентификация сервера и не проверка пользовательских сообщений. IP могут устареть; клиент может использовать другие адреса, IPv6 и media DC.

Результат Telegram выбирается только при повторном ответе всех пяти проверяемых DC; веб-сайты в его оценку не входят. В интерфейсе раздельные счётчики MTProto и веба. Ошибки транспорта и адреса доступны кнопкой «Скопировать диагностику». Диагностика не содержит аккаунтов, содержимого сообщений или секретов прокси. Если контроль успешен, он предпочтителен; иначе выбирается наиболее быстрый успешный кандидат. Прежний результат остаётся при неудаче, при этом интерфейс явно сообщает о неуспехе текущего подбора. Измерение не гарантирует работу аккаунта, медиа или звонков.

Изолированная проверка шифрования, продолжения CTR-потока, padding, nonce и правила оценки Telegram покрыта unit-тестами. Дополнительный локальный SOCKS/MTProto-сервер проверяет полный обмен обфусцированного probe, включая фрагментированный ответ и padding, без внешних запросов. Проверка на устройстве и провайдере обязательна.

Полная блокировка IP не устраняется локальными стратегиями. Встроена кнопка открытия пользовательской ссылки MTProxy в Telegram: только tg://proxy или https://t.me/proxy с server/port/secret; секрет не сохраняется, Telegram спрашивает подтверждение. Публичные прокси не подбираются автоматически. Собственный сервер/прокси приложением не предоставляется. Перед использованием внешнего прокси локальную обработку лучше выключить и проверить его отдельно.

Результаты хранятся отдельно для сервисов; одновременно действует одна стратегия. Персервисная маршрутизация стратегий и привязка к сети пока не реализованы.

Источники протокола: https://core.telegram.org/mtproto/samples-auth_key и https://core.telegram.org/mtproto/mtproto-transports . Bootstrap IP: https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/jni/tgnet/ConnectionsManager.cpp .

## Telegram WebSocket (0.4.0)
Когда прямые TCP-соединения MTProto не проходят, доступен отдельный режим: локальный MTProxy 127.0.0.1:1443 → WSS официальных DC Telegram. Root, свой сервер и аккаунт в DPI Pilot не требуются. Нажмите «Подключить Telegram через WebSocket», запустите сервис и откройте настройку прокси в Telegram второй кнопкой. Подтвердите её в Telegram. Сначала выключите ByeDPI/другие VPN; не включайте одновременно несколько режимов.

Случайный локальный секрет создаётся и хранится в приватных настройках. Из аутентифицированного MTProxy-заголовка извлекается DC ID и media-флаг. Переводится только транспортная AES-CTR-обфускация: аккаунтные MTProto-ключи и внутреннее содержимое не расшифровываются. Поддерживаются abridged, intermediate, padded-intermediate, production DC1–DC5; тестовые DC отвергаются. TLS-проверка сертификатов и имени сервера включена, редиректы не следуются. Используются только официальные имена pluto/venus/aurora/vesta/flora.web.telegram.org и варианты -1. Сторонние relay/CDN-домены не добавлялись. Документация: https://core.telegram.org/mtproto/transports .

Это альтернативный транспорт, а не подтверждённое исправление для любого провайдера. Нужны реальные проверки аккаунта, медиа и миграции DC. WSS может тоже блокироваться или отвечать редиректом; подробности доступны на экране и копируются без секретов/пакетов. Звонки не поддерживаются этим локальным MTProxy-режимом. После остановки сервиса отключите этот прокси в Telegram, иначе клиент останется направлен на остановленный localhost.

Сервис запускается с постоянным уведомлением; слушает только loopback, принимает до 24 соединений, ограничивает очередь отправки и закрывает сокеты при остановке. Автозапуск после перезагрузки и автоматическая смена маршрута пока не реализованы. Проверка правильного секрета, media DC, отклонения неверной аутентификации и полного двустороннего обмена через тестовый WebSocket включена в unit-тесты. Тестовый WS сервер работает только на localhost, без внешней сети.

Диагностика старого подбора также уточнена: SOCKS5 выполняется явно, числовые IP отправляются как IPv4, ошибки сохраняют этап и SOCKS reply code, а не один SocketException.
