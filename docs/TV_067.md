# DPI Pilot TV 0.6.7

Ранее 6/6 означало два раунда generate_204, первых 1024 байт JPEG и TLS к redirector. Это подтверждало доступность узлов, но не полную быструю загрузку превью и не видеопоток.

Теперь JPEG читается целиком без Range. Дополнительно загружаются JPEG и WebP другого публичного видео, по два запроса каждого: всего шесть полных картинок. Выборка проверяет HTTP 200 без Content-Range, отсутствие ограничения/обрыва тела, JPEG EOI или длину RIFF, реальное декодирование Android и размер не меньше 320×180 и не больше 1920×1080. Ответ ограничен 512 КиБ на картинку. Параллелизм и отмена первого отказа сохранены.

Узлы 6/6 остаются обязательными. Для допуска также нужны все шесть корректных загрузок: каждая до 8 с, типичная (медианная) до 4 с, максимальная пауза чтения до 3 с. Это пределы теста превью, не измерение битрейта видео. Сначала сравнивается стабильность/время загрузки картинок, затем задержка узлов. В отчёте и меню показаны типичное/максимальное время и паузы. Повторное заметное ухудшение во время испытания вызывает откат.

Кнопка «YouTube тормозит — сменить стратегию» сохраняет отрицательный отзыв по стабильному ID и профилю сети, исключает этот вариант до ручного сброса и проверяет резерв. По жалобе достаточно первого нового полностью прошедшего варианта, чтобы быстрее восстановить просмотр; обычный плановый цикл сравнивает всю доступную базу. Исторически рабочие команды проверяются раньше неизвестных, но не попадают в меню без новой оценки.

Автоподбор остаётся раз в 72 часа. Открытие меню, обновление базы и запуск приложения не добавляют плановых сетевых проб. Установка обновления не выбрасывает текущую сохранённую команду только потому, что старые записи не имеют метрик полных превью. Для заполнения нового списка нажмите «Проверить сейчас». Старое 6/6 без новых данных больше не даёт автоматического допуска в рабочее меню.

Если исходный тестовый файл отсутствует (404/410 или маленькая заглушка вместо превью), результат считается неопределённым: нет массового исключения команд из-за плохого источника. Набор публичных файлов проверяется перед публикацией APK. Второе видео — M7lc1UVf-VE из официального примера YouTube IFrame API: https://developers.google.com/youtube/iframe_api_reference.

Тесты: полный JPEG против 1-КиБ префикса, усечённые/ограниченные HTTP-тела, ошибочные WebP-длины, декодирование и миниатюры-заглушки, недостающие/дублированные запросы, медленные/рваные загрузки, приоритет стабильности перед пингом, сохранение метрик, старые записи 6/6 и отрицательный отзыв пользователя.

Это усиленный отбор по доступности и превью. Он не доказывает скорость каждого ролика на конкретном googlevideo-сервере и не устраняет аппаратные ограничения приставки или перегруженный Wi-Fi.
