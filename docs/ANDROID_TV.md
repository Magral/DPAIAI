# DPI Pilot TV 0.2.1

Отдельное приложение: `io.github.magral.dpipilot.tv`. Устанавливается рядом с телефонной версией. Android 5+; APK содержит ARMv7, ARM64, x86 и x86_64. Только официальные пакеты YouTube: `com.google.android.youtube.tv` и `com.google.android.youtube`.

## Первое включение

Установите APK, один раз откройте приложение и нажмите «Первоначальная настройка — один раз». Подтвердите системное разрешение VPN. Фокус кнопок выделен рамкой; управление стрелками и OK, мышь не нужна.

Автозапуск при загрузке ТВ включён по умолчанию после разрешения VPN. Если прошивка предоставляет системный пункт «Постоянный VPN», включите его для DPI Pilot TV. **Не включайте блокировку соединений без VPN**: маршрутизация рассчитана только на YouTube, остальные приложения работают напрямую.

Первый запуск после установки обязателен. Принудительная остановка приложения в настройках Android и ограничения производителя могут блокировать автозапуск. Разрешение VPN нельзя подтвердить без пользователя. Некоторые телевизоры скрывают настройки постоянного VPN; в таком случае используется BOOT_COMPLETED. Изменения прошивки/энергосбережжения проверяются на самом телевизоре.

## Автоматический цикл

- При запуске службы, открытии DPI Pilot TV, включении экрана, изменении физической сети и каждые 5 минут выполняется проверка.
- Сохранённая стратегия проверяется первой. При повторной неудаче последовательно тестируются альтернативы; одновременно работает только один движок.
- Положительный результат: два раунда — ответ YouTube generate_204, часть изображения с корректным content-type и TLS к redirector.googlevideo.com. 403/429, HTML-заглушки и пустое изображение не считаются успехом.
- Проверенные параметры сохраняются только после успешного создания VPN. При общей недоступности сети старый результат не перезаписывается; прежняя стратегия восстанавливается по возможности. Повторные попытки: через 1, 2, 5, затем 10 минут.
- Полный транспорт видеоролика и скорость воспроизведения не проверяются: TLS googlevideo проверяет доступность узла, а не доставку конкретного видео. Для установщика ручной переподбор доступен в сервисном меню; зрителю он не требуется.

## Маршрутизация и изоляция

В allowlist только установленные официальные клиенты YouTube. Пустой allowlist не устанавливается. Только UDP/443 для этих клиентов отклоняется TV-сборкой движка, чтобы YouTube использовал TCP. DNS/UDP и TCP/443 сохраняются; отдельный C-тест проверяет это для IPv4 и IPv6. DNS берётся из физической сети телевизора. Остальные приложения и исходящие соединения самой утилиты не идут в TUN. IPv6 не включается в VPN-конфигурацию; отдельный IPv6-обход не заявлен.

Каждый экземпляр ByeDPI запускается в отдельном процессе :engine. Перед сменой стратегии VPN закрывается, привязка к процессу снимается и ожидается его завершение; C globals не переиспользуются. Служба VPN сразу показывает постоянное уведомление, сохраняет выбор, поддерживает START_STICKY и системный запуск always-on. При отзыве разрешения останавливается. Автоматический запуск YouTube поверх других приложений не выполняется.

## Сборка и подпись

`bash gradlew :tv:assembleRelease :tv:testReleaseUnitTest`

Ключ тот же постоянный ключ проекта. Условия выпуска — docs/SIGNING.md. CI сверяет сертификат, запускает тесты порядка fallback, ограничений health checks и отдельный нативный тест выборочного запрета QUIC. Телефонный APK не заменяется. TV-релизы имеют теги tv-vX.Y.Z и не меняют latest телефонного приложения. Выпуск запускается вручную через Signed Android TV release либо изменением tv/release-request.txt вместе с увеличением версии.

Документация Android: https://developer.android.com/develop/connectivity/vpn
https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start

Первый релиз требует проверки на реальном телевизоре: пульт, выключение/включение, смена сети, холодная загрузка, отзыв VPN и воспроизведение YouTube. Проверка сборки и JVM-тестов не заменяет эти испытания.


## Режим для зрителя без технических навыков (0.2.0)

Первоначальную настройку выполняет установщик: разрешить VPN, разрешить фоновую работу и оставить автозагрузку включённой. Если прошивка предоставляет постоянный VPN, включить его без блокировки соединений вне VPN. Затем открывать DPI Pilot для обслуживания стратегии не требуется. На обычном экране только статус и кнопка открытия YouTube. Сервисное меню: кнопка Menu пульта либо долгое OK на заголовке. Отключение помощника требует отдельного подтверждения.

Добавлен автоматический профиль ByeDPI с переходом между методами при reset/ошибке TLS и IP-кэшем. Нативный тест запускает настоящий движок, принудительно обрывает первое подключение локального сервера и проверяет, что запрос автоматически доходит через повторное соединение.

Для каждой сети (хэш интерфейса и DNS, без чтения SSID) хранятся три проверенные стратегии. После отказа резервные проверенные варианты идут раньше непроверенных. Повторное сохранение разрешено только после health checks и успешного создания VPN; общий сбой интернета не стирает историю.

Наблюдение за счётчиками TUN проверяет длительное отсутствие данных при повторных исходящих запросах. Это консервативная эвристика, не анализ просмотра: при простое и небольших обменах телеметрии стратегия не меняется. При подозрении на зависание она автоматически переключается и временно исключает этот вариант из подбора на 15 минут. Успешный большой входящий поток снимает временное исключение.

Служба публикует heartbeat раз в 30 секунд бодрствования. Для признака зависания используется uptime без глубокого сна: выключенный экран и сон сами по себе не вызывают аварийный перезапуск. Persisted JobScheduler служит резервной проверкой примерно каждые 15 минут (Android может отложить выполнение). Если служба завершилась, он пытается запустить её там, где Android разрешает фоновый старт; на Android 12+ для этого нужна выданная установщиком отмена оптимизации батареи. Если живой процесс перестал обслуживать цикл более трёх минут, watchdog может завершить только собственный процесс, чтобы Android восстановил sticky VPN. Такое восстановление ограничено одним разом за 30 минут.

Это не обещание вечного обхода любой блокировки: локальные методы могут не помочь при недоступных IP; эвристика счётчиков не доказывает воспроизведение каждого ролика. Принудительная остановка пользователем и запреты прошивки не обходятся. Нужны испытания полного цикла на конкретном ТВ, включая длительный просмотр и многократный сон/пробуждение.


## Исправление запуска VPN (0.2.1)

В 0.2.0 при первой настройке VPN создавался только после всех предварительных проверок; отказ одного тестового узла оставлял устройство вообще без туннеля. Теперь после готовности движка интерфейс создаётся до сетевых тестов. При исчерпании вариантов без сохранённой стратегии остаётся включённым адаптивный профиль; это предварительный вариант, а не подтверждённый успех. История успешных стратегий по-прежнему записывается только после прохождения проверок.

На экране отдельно указаны создание VPN и результат проверок. В техническом отчёте отображаются версия, модель/API Android, разрешение, служба, VPN-интерфейс и найденные пакеты YouTube. Ошибки запроса запуска службы больше не скрываются. Значок VPN в оболочке не заменяет проверку интерфейса и фактического просмотра.
