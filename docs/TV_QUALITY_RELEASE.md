# DPI Pilot TV 0.5.1: качество и восстановление

Отдельный подписанный APK Android TV с прежним applicationId и сертификатом. Устанавливается поверх TV 0.4.1. База из 279 вариантов и ByeDPI 17.3 остаются. Изменения не переносятся в телефонный APK автоматически.

## 1. Доставка медиаданных

После двух раундов обычных проверок приложение пытается прочитать `ytInitialPlayerResponse` публичного образца `jNQXAC9IVRw` и использовать прямой URL video/* из streamingData. Выполнение JavaScript, расшифровка signatureCipher, аккаунт, cookies пользователя и обход требований авторизации не применяются. При отсутствии доступной прямой ссылки медиатест имеет статус UNAVAILABLE, не FAILED. Google может менять формат страницы или требовать подтверждения; в таком случае реальная доставка видео не оценена.

Для доступной ссылки разрешены только HTTPS/443, без userinfo, путь /videoplayback и поддомен googlevideo.com. Два новых соединения запрашивают один и тот же первый Range-фрагмент до 128 КиБ. Проверяются код 206, Content-Range, video/*, размер и полнота тела. Измерения включают установление соединения, TLS и передачу, показывают консервативную оценку минимальной скорости именно этих запросов и их повторяемости. Это не скорость полного ролика, не проверка декодера и не гарантированная доступность всех CDN пользователя.

403/401/404/410/416/429 для временной ссылки означают недоступность теста, а не доказанный отказ DPI. Ссылка хранится только в RAM до трёх минут, сбрасывается при изменении сети и отказе сервиса. Полный URL, query/signature, JSON страницы и содержимое фрагмента не сохраняются в журнал или историю. Redirect ограничен тремя переходами и списком доверенных хостов. HTTP/1.1 parser ограничивает заголовки/тело, поддерживает chunked и отклоняет обрыв/неоднозначное framing. Сертификаты и hostname проверяются.

Медиапроверки вместе с метаданными ограничены примерно 32 МиБ за скользящие 24 часа (одно чтение буфера может пересечь границу на несколько КиБ). Счётчик сохраняется после каждой пробы, перевод часов назад не обнуляет расход. Это ограничение относится к новым медиатестам; прежние небольшие проверки узлов считаются отдельно. На один результат — до 2 МиБ HTML и два небольших фрагмента. Общая проба ограничена тремя минутами и отменяется закрытием сокета.

## 2. Сравнение кандидатов

Быстрые проверки проходят по блоку до 12 вариантов; до трёх подходящих кандидатов получают медиатест. Выбор сравнивает качество нескольких кандидатов с текущим. Полная медиадоставка имеет приоритет над отсутствием измерения. Для обычной смены требуется не менее 25% улучшения измеренной скорости без заметного ухудшения повторяемости/задержки; без медиаданных — существенное улучшение средней задержки двух раундов. Ошибочный кандидат не становится лучшим из-за быстрого отказа.

Исправное соединение может дополнительно оптимизироваться при отсутствии заметного полезного потока, не чаще раза за шесть часов. Полезный поток сохраняет защиту активного туннеля. Сравнение не доказывает глобальный оптимум из всей базы: кандидаты проверяются постепенно с сохранением позиции.

## 3. Признаки зависания

Счётчики активного TUN продолжают опрашиваться во время фоновой диагностики; собственные пробы идут вне TUN. За 45-секундное окно повторные запросы почти без ответов дают сильный признак зависания. Два последовательных окна с заметным спросом и менее 64 КиБ входящих данных дают дополнительный признак устойчивого дефицита. Пауза, небольшая телеметрия и длительный перерыв измерений после сна не считаются непрерывным отказом. Это эвристика сетевого обмена: картинку, паузу плеера и текущий битрейт приложение непосредственно не видит.

## 4. Пробная смена и откат

Перед сменой сохраняются IDs предыдущего и нового варианта, профиль сети и отметка времени. Новый активный вариант проверяется и наблюдается до двух минут до фиксации. Повторно подтверждённое ухудшение контрольных/медиапроб или сильный признак зависания после 45 секунд могут вернуть предыдущий вариант; фоновая проба прерывается для быстрого отката. Вариант, который уже был признан зависшим до смены, не считается надёжным резервом для возврата.

Неудачный кандидат исключается из подбора на 30 минут, исключения сохраняются для профиля сети. Незавершённая смена после перезапуска возвращает прежний вариант, если запись свежая и он был пригоден для возврата. При смене физической сети прошлое испытание не переносится на новую сеть. Откат пересоздаёт соединение и может вызвать паузу. Если ни старый, ни новый вариант не работает, гарантировать восстановление невозможно.

При отсутствии активности пользователя можно подтвердить только пробы, а не стабильный просмотр: история помечает полезный обмен отдельно.

## 5. История качества

Для хэша интерфейса/DNS и стабильного ID команды сохраняются положительные/отрицательные проверки, признаки зависания, откаты, измеренные медиапараметры, время активности и полезного входящего обмена. Интервалы простоя не увеличивают полезное время. При старте ранжируются подтверждённые резервы; устойчивый полезный обмен без отказов может учитываться отдельно даже при неполной диагностике. Прошлый опыт не доказывает текущую доступность: после старта выполняется новая проверка.

Профиль определяется без SSID/location permission; разные Wi-Fi с одинаковыми интерфейсом и DNS могут совпасть. Время полезного обмена не является учётом просмотренных роликов. История не содержит названий роликов или аккаунтов.

## 6. Автономность и отчёт

Кнопка «Проверка автозапуска» показывает enabled/boot, компонент получателя загрузки, системное разрешение VPN, доступность фонового старта, назначенную резервную задачу, heartbeat и фактические записи BOOT_COMPLETED/запуска/watchdog текущего сеанса. Отсутствие испытания перезагрузкой отображается отдельно. Эта кнопка не перезагружает приставку, не убивает процесс ради имитации и не доказывает отсутствие ограничений прошивки.

«Экспорт отчёта» / «Сохранить файл» открывает системный ACTION_CREATE_DOCUMENT для text/plain. Можно выбрать доступную USB-память или другой provider. Дополнительные разрешения на общее хранилище не запрашиваются; при отсутствии системного picker остаётся копирование текста. В отчёте есть данные качества, состояние испытания/отката и проверка автономности; подписанные медиассылки отсутствуют.

## Проверки и пределы релиза

JVM-фикстуры: framing/chunked/обрывы, Content-Range/тип/размер, direct-only JSON и запрет чужих хостов, quality/hysteresis, откат и непригодный предшественник, репутация без награды за простой, бюджет/перевод часов, устойчивый дефицит/пауза/сон. Нативные проверки: все 279 команд, JNI, reset/replay, изоляция процессов, DNS без UDP-фейков и guard UDP/443. Сборка всех ABI, постоянный сертификат и состав APK проверяются CI.

Доступность прямых видеоссылок в текущем YouTube, реальное воспроизведение, D-pad/USB-picker и холодный старт на физической X96 не проверяются в CI. Телеметрия не заменяет эти испытания. При ограничениях выдачи ссылок приложение продолжает работу с обычными пробами и наблюдением трафика, явно показывая отсутствие медиамерки.
