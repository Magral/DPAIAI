# DPI Pilot mobile 0.7.0 — Instagram и YouTube одновременно

На главном экране есть кнопка **Включить Instagram + YouTube**. Выключите прежний VPN, нажмите кнопку и подтвердите стандартное разрешение Android, если оно запрошено. Оба установленных официальных клиента добавляются в VPN сразу. Ручной подбор предварительно не обязателен: берутся сохранённые отдельные команды, при их отсутствии — стартовые `--split 1` для Instagram и `--disorder 1` для YouTube. Стартовые команды не объявляются проверенными.

В меню подбора есть совместная цель и прежние отдельные цели. Совместный подбор ищет результат отдельно для каждого сервиса, затем проверяет пару через реальный движок на тестовом порту. Команды и курсоры сервисов сохраняются независимо.

## Как разделяются стратегии

Один TUN и один процесс ByeDPI 17.3 обслуживают оба клиента. Локальный структурированный план содержит две проверенные по строгому списку параметров команды. План не является строкой запуска из удалённого каталога. При сборке argv программа добавляет собственные фиксированные списки доменов ко **всем** группам каждой команды, включая группы `--auto`. Разделитель доменов внутри одного аргумента сохраняется; строка с доменами не разбивается оболочкой.

Движок выбирает правила по HTTP Host или незашифрованному TLS SNI. Это работает и при передаче из TUN только числового адреса назначения. Доменный кеш движка учитывает имя сервера. Последняя группа пропускает прочие домены выбранных клиентов без преобразований; DNS UDP/53 остаётся отдельной начальной группой, UDP/443 блокируется, чтобы клиент использовал TCP. Другие приложения не добавляются в VPN автоматически. Набор доменов покрывает Instagram/API/CDN/Meta и YouTube/API/превью/googlevideo/авторизацию. ECH, отсутствующий или нераспознанный SNI не позволяет выбрать доменную стратегию — применяется обычная группа без преобразования.

Ограничиваются и суммарное число групп (30), и argc (512), чтобы два профиля укладывались в ограничения закреплённого native-парсера. Неподходящие сочетания не запускаются; каталог и его проверка подписи не ослаблены.

## Фоновый контроль

В совместном режиме последовательно проверяются оба сервиса. Для не прошедшего проверки сервиса перебираются его кандидаты из обновляемой базы. Кандидат сначала испытывается отдельно, затем в доменной паре на тестовом порту. После активации повторно проверяется изменённый сервис и ранее проходивший проверки второй сервис; при провале восстанавливается прежняя пара. Когда оба сервиса изначально недоступны, разрешено исправить их по очереди: неудача ещё не исправленного сервиса не блокирует улучшение первого.

Успешная замена не меняет сохранённую команду другого сервиса. Перезапуск общего процесса может кратковременно переподключить оба клиента. Остановленный VPN не восстанавливается ради завершения проверки. Подтверждённые узлы отображаются отдельно по сервисам. Проверка повторяется через пять минут при успехе, при неудаче поиск продолжается через минуту. В совместном режиме общий счётчик трафика TUN не используется для вывода, какой из двух сервисов работает: трафик одного не считается доказательством работоспособности другого.

Проверки показывают доступность транспортных узлов и публичных ответов. Вход, Direct, лента, Reels и реальное воспроизведение требуют проверки на устройстве и сети пользователя.

## Проверки выпуска

- JVM: сохранение независимой команды при замене второй, ограничения плана и каталога, разметка адаптивных групп, несовместимые и повреждённые планы, прежние тесты подписанного канала и тайм-аутов.
- Native/JNI: точный argv, экспортированный из Kotlin unit-теста, запускается через production JNI. Восемь одновременных HTTP и четыре TLS-соединения идут на один числовой SOCKS-адрес и один порт сервера. Проверяются разные преобразования Instagram/YouTube, неизменённый третий домен, домен с ложным суффиксом, целостность ClientHello и разделение TLS-записей только для Instagram.
- CI: сборка четырёх ABI, проверка постоянного сертификата и структуры APK. Прежние ТВ- и Windows-релизы не заменяются.
