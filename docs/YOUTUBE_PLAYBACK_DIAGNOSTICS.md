# YouTube: диагностика меню и медиадоставки

Выпуски: телефон0.12.2, TV0.6.13, Windows0.2.1. Это инструмент для установления причины, а не заявление об исправлении блокировки.

Пользователь наблюдает сбой на телефоне/приставке, Wi-Fi/мобильной сети, DPI Pilot/ByeByeDPI; платный VPN помогает. Внешняя сеть и способ ограничения пока не установлены. Аналогичные наблюдения в upstream: https://github.com/Flowseal/zapret-discord-youtube/issues/18725 (10–13ноября2026). Отчёты других пользователей не доказывают механизм на этой сети.

## Как сравнить

1. Остановите собственный обход DPI Pilot. Откройте «Диагностика меню и видео YouTube», нажмите «Текущая сеть / платный VPN» и сохраните отчёт обычной сети.
2. Включите платный VPN, который включает в маршрут само приложение DPI Pilot. Повторите системный тест, сохраните второй отчёт. Один браузерный VPN-плагин не покрывает диагностическое приложение Windows.
3. Для отдельного теста локального движка включите DPI Pilot и выберите «Работающий DPI Pilot». Диагностика сама не включает/выключает VPN и не переключает стратегии.

Android: кнопка на главном экране смартфона; на ТВ в дополнительных настройках. Windows: кнопка на основной панели. Стоп закрывает диагностические сокеты; просмотр/игры и рабочие профили не изменяются.

## Что доказывают результаты

- 6/6: ограниченная доступность узлов прежнего теста; это не проверка меню/видеопотока.
- DNS: отдельно системные ответы и ответы публичного DNS через текущий системный маршрут. Различия нормальны для CDN, сами по себе не доказывают подмену. При локальном SOCKS системный DNS не обязательно совпадает с разрешением имени самим прокси.
- API: настоящий JSON player и playabilityStatus; HTTP200/TLS без корректного JSON не подтверждает API. Это публичные sample-запросы, не авторизованная лента/меню конкретного клиента.
- CDN: report_mapping — подсказка о карте кэшей, не доказательство загрузки видео.
- Медиа: свежие публичные URL из двух player/watch sample-ответов. До четырёх запросов по256КБ; проверяются HTTP, media MIME, префикс MP4/WebM, минимум32КБ и измеренная скорость. Порог512Кбит/с диагностический, не оценка пригодности для HD/4K.
- HTTP403/404/410/429 или отсутствие публичной ссылки (consent/login/signature/SABR) — неопределённый тестовый источник. Стратегии не исключаются. Отказ/низкая скорость фактической медиапередачи выводятся отдельно.

Нет cookies/аккаунта/истории пользователя; подписанные query URL не сохраняются в отчёте. TLS и hostname проверяются. Редиректы не выполняются, медиа допускается только по HTTPS443 на поддоменах googlevideo.com. Контрольный запрос gstatic и публичный DNS — отдельные диагностические обращения, не системная перенастройка.

Если в обычной сети медиабайты не приходят/очень медленные, а через VPN на том же устройстве приходят, это свидетельство зависимости от внешнего маршрута. Чтобы отличить DPI от ограничений CDN/IP, нужны сами парные отчёты; без них нельзя обещать локальный способ исправления. Диагностика не расшифровывает чужой TLS и не измеряет фактическое декодирование/воспроизведение всех роликов.

Видеодорожка и отдельная аудиодорожка выбираются по MIME, а не по первым двум URL. Отсутствующее аудио отмечается как не проверенное; общий медиатест не объявляется полностью подтверждённым без обоих видов. Видимая смена сети/VPN или адресов/DNS во время теста отменяет результат, старые адреса образца не используются для нового маршрута. Скрытую смену выходного сервера внутри стороннего VPN с тем же интерфейсом ОС определить не может; во время одного теста не меняйте VPN/локацию.
